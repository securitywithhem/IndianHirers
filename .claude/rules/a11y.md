# Accessibility — WCAG 2.1 AA

## Contrast pairs allowed

Ratios computed from the token values in `globals.css` (`node scripts/contrast.mjs`).
Body text needs 4.5:1; large text (≥ 24px, or ≥ 18.66px bold) and UI boundaries/icons
need 3:1. Rows marked **tbm** are estimates still **to be measured** with the script;
do not rely on one that has little headroom until it is.

The semantic role each pair comes from is in brackets — inside `.theme-dark` the roles
re-map, so `text-foreground` on `bg-background` is always an allowed pair.

### On ivory (default scope and `.theme-light`)

| Foreground | On | Ratio | Use |
|---|---|---|---|
| `espresso-900` [`foreground`] | `ivory-50` / `ivory-100` | 16.76 / 15.23 | all text |
| `espresso-600` [`muted-foreground`] | `ivory-50` / `ivory-100` | 7.45 / 6.77 | secondary text, captions, placeholders |
| `maroon-700` [`heading`, `link`, `primary`, `ring`] | `ivory-50` / `ivory-100` | 10.20 / 9.27 | headings, links, outline-button text and border, focus ring |
| `gold-700` [`kicker`] | `ivory-50` / `ivory-100` | 5.93 / 5.39 | eyebrows and small gold labels — the only gold that is text on ivory |
| `ivory-50` [`primary-foreground`] | `maroon-700` / `maroon-800` | 10.20 / 12.65 | primary button label, rest / hover |
| `danger` [`destructive`] | `ivory-50` / `ivory-100` | ~6.7 / ~6.1 **tbm** | form error text and invalid-field border |
| `control-border` [`input`] | `ivory-50` / `ivory-100` | 4.47 / 4.06 | input, textarea, chip boundary (UI, needs 3:1) |
| `gold-500` [`hairline`] | `ivory-50` | 2.21 | **lines, icons-as-ornament and large shapes only — never text, never a control boundary** |
| `ivory-300` [`border`] | `ivory-50` | ~1.45 **tbm** | decorative structural rule only — no requirement, never a control boundary |

| Foreground | On | Ratio | Use |
|---|---|---|---|
| `ivory-50` [`foreground`, `heading`] | `maroon-950` / `maroon-800` / `maroon-700` | 16.51 / 12.65 / 10.20 | all text |
| `ivory-300` [`muted-foreground`] | `maroon-950` / `maroon-800` / `maroon-700` | ~11.4 / ~8.7 / ~7.0 **tbm** | secondary text |
| `gold-300` [`kicker`, `link`, `ring`] | `maroon-950` / `maroon-800` / `maroon-700` | 10.77 / 8.26 / 6.65 | eyebrows, links, gold text, focus ring |
| `gold-500` [`primary`, `hairline`] | `maroon-950` / `maroon-800` | 7.48 / 5.74 | text, icons, outline-button text and border |
| `gold-500` | `maroon-700` | 4.62 | text ≥ 16px only — little headroom; prefer `gold-300` |
| `maroon-950` [`primary-foreground`, `accent-foreground`] | `gold-500` / `gold-300` | 7.48 / 10.77 | type on a gold fill, rest / hover; also on `.gold-sheen` |

### Special surfaces

| Foreground | On | Ratio | Use |
|---|---|---|---|
| `espresso-900` | `whatsapp` | 9.30 | label and icon on WhatsApp green |
| `ivory-50` | `.hero-scrim` over any photograph | ≥ ~4.7 **tbm** | hero and transparent-header text; the scrim is never lighter than 62% `maroon-950` |
| `gold-300` | `.hero-scrim`, lower 40% of the hero only | ≥ ~5.4 **tbm** | hero eyebrow; elsewhere on the scrim use `ivory-50` |
| `ivory-50` / `gold-300` | `.candle-glow` over `maroon-800` | ~9.3 / ~6.1 **tbm** | headings in the glow; **`gold-500` text is not allowed over the glow** (~4.2) |
| `espresso-600` / `gold-700` | `.surface-linen` over `ivory-100` | ~6.5 / ~5.1 **tbm** | the weave costs at most ~0.3 on any ivory pair |

**Forbidden:** `gold-500` or `gold-300` as text on ivory (2.21 / lower) · `ivory-50`,
`ivory-100` or stock `white` on a gold fill (2.21) · any light type on `whatsapp`
(~2:1) · `gold-700`, `maroon-700`, `espresso-*` or `danger` as text on any maroon
surface (all below 3:1) · type of any colour on `bg-gold-gradient` (its dark end fails;
use `.gold-sheen` for a fill that carries type) · opacity modifiers on text colours
(`text-foreground/60`) — use `muted-foreground` instead · `control-border`, `gold-*`
or `ivory-300` as a focus ring on ivory.

Disabled controls (`disabled:opacity-50`) are exempt from contrast under WCAG 1.4.3, but
must still carry `disabled` / `aria-disabled`.

A new pair is allowed only after its ratio is computed and added to this table and to
`docs/color-system.md`.

## Focus

- Every interactive element shows a visible `focus-visible:` ring: 2px, `ring-ring`,
  with a 2px offset in `ring-offset-background`. The class **`focus-ring`** applies
  exactly that. `ring` re-maps with the scope: `maroon-700` on ivory (10.20), `gold-300`
  inside `.theme-dark` (≥ 6.65). Gold is never the focus colour on ivory.
- On a filled button the ring sits outside the 2px offset, so it is judged against the
  surface around the button, not against the fill — the same class works on gold,
  maroon and WhatsApp-green buttons.
- Use `focus-visible:`, never bare `focus:`. Never remove an outline without replacing it.
- Focus order follows visual order. No positive `tabIndex`.

## Structure

- Skip link is the first focusable element and targets `#main-content`.
- Exactly one `<main>` per page — it is in `layout.tsx`; pages must not add another.
- One `<h1>` per page; heading levels never skip. Card titles take their level from
  a prop, not a fixed tag.
- Landmarks: `header`, `nav` (each with a distinct `aria-label`), `main`, `footer`.
- Touch targets ≥ 44×44px with ≥ 8px between them.

## Alt text

- Product and event photos: describe what is in the frame (material, colour, pattern,
  piece), in content files. Never "image of", never the filename.
- Decorative images, textures and repeated logos: `alt=""` plus `aria-hidden`.
- Icons beside visible text are `aria-hidden`; icon-only controls need an `aria-label`.

## Keyboard

**Mobile drawer:** trigger is a `<button>` with `aria-expanded` and `aria-controls`.
On open, focus moves into the drawer and is trapped there; `Esc` closes; on close,
focus returns to the trigger. Background is `inert` and does not scroll. The drawer
is `role="dialog"` `aria-modal="true"` with a label.

**Carousel:** a labelled region (`aria-roledescription="carousel"`). Previous/next are
real buttons, reachable by Tab, with labels. Arrow keys move slides when the carousel
has focus. No auto-advance; if ever added, it needs a visible pause control and stops
on focus or hover. Off-screen slides are not focusable. It must remain a plain,
scrollable list without JavaScript and under reduced motion.

**Forms:** every input has a visible `<label>`; errors are text, linked with
`aria-describedby`, and announced; required fields are marked in the label.
